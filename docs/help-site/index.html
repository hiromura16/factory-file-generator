ファイル生成ツール 操作マニュアル

取り込み側がファイル形式、分割、完了通知を解釈できるか検証します。指定件数の合成データをJSON・CSV・疑似画像などにし、ランディング領域へまとめて書き出します。

最初に試すこと

CSVを30行作り、10行ずつ3ファイルに分ける。VMのランディングフォルダにCSVが3本でき、実行履歴に完了が表示されます。

Docker Compose導入手順で準備し、VMで http://127.0.0.1:3561/ を開きます。

「出力先」でローカルランディングを選びます。ランディングとは、取り込みツールが新しいファイルを探しに来る受け渡し用フォルダです。見るだけなら、見本の段階までで十分です。

  1. 「ファイルをつくる」で「保存した設定を使う」を開き、「小さく試す」を選んで「ひな型を読み込む」を押します。
  2. 「CSVだけ」を選び、生成する件数を 30 にします。「詳細設定 → 形式ごとの詳細と完了通知」で「ファイルあたりの件数」を 10 にします。
  3. 「サンプルを確認」を押します。1行目が列名（ヘッダー）で、その下がデータです。区切り文字と文字コードが取り込み側と揃っているか見ます。
  4. 「ファイルを出力する」で保存先を照合し、実行します。「実行履歴」に完了が出たら .env の LANDING_DIR でデータCSV3本を探します。完了通知用のファイルがある場合は別に数えます。

よくある質問

見本を作ると保存先にも書き込まれますか？

見本は画面内の確認です。保存先への書き込みは出力を実行した時点で始まります。

CSVを受け取ったのに取り込み側が動きません

取り込み側が完了印を待っている場合は、実行履歴と、完了通知形式に対応するマニフェストまたは完了ファイルを確認します。

CSVの列名や並びはどこで変更しますか？

「詳細設定」のデータ項目と生成ルールで、列として出す項目名と順序を編集し、もう一度見本を出します。

停止と再起動

ジョブは完了すると停止します。途中停止を選んだ場合は部分出力が残ることがあるため、取り込み側で完了印を確認します。

想定した結果が出ないとき

実行履歴が失敗の場合は出力先の権限と空き容量を先に確認します。ファイルが見えてもマニフェストのないバンドルは、マニフェスト待ちの収集では未完了の扱いです。

書き出されるファイルを確認する

形式 詳細設定の入口 受け取り側で確認すること
JSON JSONの書式・テンプレート 配列、1件1ファイル、JSON Linesを区別し、入れ子のキーを照合する。
CSV 区切り、ヘッダー、文字コード 結合する列とUTF-8／BOMの有無を確認する。
画像 寸法、色、間引き PNG/JPEGの形式とレコードとの対応を確認する。
Excel・XML シート名、ルートと行の要素名 ブック内の列、またはXML要素の形を確認する。
Parquet・Avro 圧縮、Avroのレコード名 読み取り側の列型と、圧縮方式の対応を確認する。
PDF ページの向き、列 列の並び、文字の幅、ページを確認する。

標準の完了通知は、生成ファイルの一覧・バイト数・SHA256などを含む .ready.json です。出力例では、1バッチのデータファイルと完了通知が同じバッチの保存場所に並びます。取り込みの開始は完了通知を見て判断します。

更新率・削除率は、合成列 file_event_operation の抽選確率です。既存ファイルを上書き・削除する操作とは独立しています。

json_template はJSONの本文に適用されます。CSV・XLSXなどは同じ生成項目を平らな行として展開します。ファイル名は path_template と filename_template で変えられます。

たとえば試験の実行キーと実行IDを出力パスに使う構成では、各実行の下に次のようにまとめられます。

<run_key>/<job_id>/
  csv/records_00001.csv
  csv/records_00002.csv
  csv/records_00003.csv
  manifests/<バッチ名>.ready.json

完了マニフェストの artifacts を見ると、各ファイルの path、サイズ、SHA256を照合できます。実際のファイル名とマニフェストの数はバッチ条件とファイル名テンプレートに従います。
